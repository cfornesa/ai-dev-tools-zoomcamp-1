## Genuinely actionable gaps

### #414 — Shared production AI quota state

Evidence: `backend/scenes/ai_api.py` documents process-local cache behavior for
rate limits, while `backend/backend/settings.py` has no shared cache
configuration. Impact: requests distributed across production workers may
bypass the documented per-minute and daily limits, increasing cost-abuse and
provider-exhaustion risk.

Status: open, high priority, infrastructure/dependency decision required.
The issue contains the two-worker acceptance test, 429 boundary, production
configuration checks, exact focused/full verification, and out-of-scope
limits.

### #415 — Production WSGI/ASGI server

Evidence: the production launcher reaches `manage.py runserver`. Impact:
Django’s development server is unsupported for production and weakens
concurrency, lifecycle, and reliability guarantees.

Status: open, high priority, deployment/server-choice decision required.
The issue contains the production-only launcher criteria, signal/readiness
requirements, local-development compatibility checks, and exact verification.

### #416 — Explicit signup authentication policy

Evidence: `docs/plan.md` describes Google-only V1 identity while account
settings/templates expose password signup and default email verification is
disabled. Impact: the supported identity policy is ambiguous and may permit
unverified account creation or signup abuse.

Status: open, product/security decision-blocked. The owner must choose
Google-only authentication or verified password signup with mandatory
production abuse protection; the issue then requires settings, templates, and
tests to enforce that single policy.
