# Local-first entry points and test-harness boundaries

Recorded 2026-10-11 from #1346/#1347 (PR #1348, merge `442444851ac8`). Evidence is cited per fact; nothing here is a design decision.

**1. `/create` "Start blank" is server-backed; local-first creation is Studio's menu.** At base `4175e4e6`, the server-backed `/create` chooser's "Start blank" calls `createChooser2DProject` / `createChooser3DProject` (`POST /api/projects/blank/`, `POST /api/projects3d/`) and opens a server editor. Local-first creation is Studio's `More creation options` menu (`/studio`): `Create a new 2D project with p5.js|Canvas2D|SVG`, `Create a new 3D project`, `Create a local generated piece`, which create IndexedDB records and open `/local-projects/:id` or `/local-generated/:id`. Specs that assert local-only creation and no server create POST must use the menu, never the chooser. Evidence: code reading and the #1346 QA run (20 passed / 3 failed, classified). Open issues that may change this: #1306 (canonical local 3D URL and menu), #1349 (remaining stale generated-piece setups).

**2. Playwright `globalSetup`'s `uv run` can sync a shared venv.** The fixture command shells out to `uv run`; without `UV_NO_SYNC=1` (plus `UV_FROZEN=1` and a `UV_PROJECT_ENVIRONMENT` that already matches `backend/uv.lock`) it may install or remove packages in the venv it points at. Observed once on 2026-10-10: "Uninstalled 1 package / Installed 1 package" in the primary checkout's backend venv. The package was not named in the log; `mcp` 1.30.0 -> 2.3.0 is inferred from the lock and a dist-info timestamp, and the prior state was not snapshotted. Use the no-sync controls and an existing compatible venv.

**3. Vitest collects `*.spec.ts` outside `e2e/`.** Vitest's default include matches any `*.spec.ts` under the frontend root; a Playwright spec placed elsewhere (for example `frontend/diagnostics/`) fails Vitest collection ("The URL must be of scheme file") and would fail `npm test`. `vite.config.ts` `test.exclude` lists `e2e/**`, `scripts/**` and, since #1347, `diagnostics/**`. Evidence: `vitest list --filesOnly` and a single-file run during the #1346/#1347 review.
