# Playwright E2E support helpers

Use these helpers as the boundary between a spec and shared application setup or UI contracts. Prefer the helper whenever it owns the behavior under test; keep assertions about the scenario's outcome in the spec.

The browser suite needs a running Vite/Django stack backed by disposable PostgreSQL, plus Playwright's browser binaries. `globalSetup` checks readiness and creates fixture users; `globalTeardown` cleans them up. See the repository's `AGENTS.md` E2E instructions before running the suite. Helpers that mutate fixtures require an explicit disposable target.

## Recipes

These are starts, not complete assertions for every editor feature. The snippets use the configured Playwright fixtures and the shared setup contracts.

### Signed-in 2D editor

```ts
import { expect, test } from '@playwright/test';

import { loginViaUI } from './support/auth.js';
import { createServerProject2D } from './support/createProject.js';
import { requireE2EFixtures } from './support/prerequisites.js';

test('starts in a signed-in 2D editor', async ({ page }) => {
  const fixtures = requireE2EFixtures();
  await loginViaUI(page, fixtures.owner.email, fixtures.password);
  const projectId = await createServerProject2D(page);

  await expect(page).toHaveURL(/\/users\/@[^/]+\/edit\/[^/]+\/?$/);
  expect(projectId).toBeTruthy();
});
```

### Signed-in 3D editor

```ts
import { expect, test } from '@playwright/test';

import { loginViaUI } from './support/auth.js';
import { createServerProject3D } from './support/createProject3d.js';
import { requireE2EFixtures } from './support/prerequisites.js';

test('starts in a signed-in 3D editor', async ({ page }) => {
  const fixtures = requireE2EFixtures();
  await loginViaUI(page, fixtures.owner.email, fixtures.password);
  const projectId = await createServerProject3D(page);

  await expect(page).toHaveURL(/\/users\/@[^/]+\/edit\/[^/]+\/?$/);
  await expect(page.getByTestId('scene3d-preview-canvas-frame')).toBeVisible();
  expect(projectId).toBeTruthy();
});
```

### Anonymous public page

```ts
import { expect, test } from '@playwright/test';

test('starts on the public gallery without signing in', async ({ page }) => {
  await page.goto('/gallery');

  await expect(page.getByRole('heading', { name: 'AugmentrART' })).toBeVisible();
  await expect(page.getByRole('link', { name: 'Login', exact: true })).toBeVisible();
});
```

For a specific anonymous project page, first publish a disposable fixture project and use the public URL returned by the publication response; do not hard-code an ID from another run.

## Known stale patterns

| Avoid                                                                                                      | Current contract                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Navigating to legacy `/ai-projects`, `/ai-projects/*`, or `/ai-projects3d/*` routes                        | Create/open the canonical editor, then use `createServerProjectAndOpenAIProposalPanel(page, '2d' \| '3d')` for its current Ask AI panel.                              |
| `getByRole('menuitem', { name: 'Create an AI-assisted animation' })` or `Create an AI-assisted 3D project` | Use the current local-first creation UI when creation is under test; for an AI proposal scenario use `createServerProjectAndOpenAIProposalPanel(page, '2d' \| '3d')`. |
| `name: 'Save', exact: true` for the scene Save                                                             | Use `saveScene(page)` or the canonical `Save scene` accessible name in the Primary editor actions group.                                                              |
| `locator('summary')` for editor sections                                                                   | Use `expandSection(page, 'Section name')` or `expandAllCollapsibleSections(page)`.                                                                                    |
| `More creation options` and its retired menu items                                                         | Use the current `/create` local-first flow for UI-creation behavior; use server-backed helpers for persisted editor setup.                                            |
| Clicking the sr-only `Open piece controls menu` compatibility button                                       | Use `openPieceControlsMenu(page)`; inline toolbars expose their actionable controls directly.                                                                         |
| Reimplementing fixture API CSRF headers or session setup                                                   | Use `apiPost`/`apiPatch`/`apiPut`/`apiDelete` and `loginViaUI`.                                                                                                       |

There is no shared publish-dialog helper in `frontend/e2e/support/` at this revision. `publishingAndRemix.spec.ts` has a spec-local `confirmPublish` flow because it owns that suite's publication assertions; #1174 did not add a support module. Keep publication expectations with their owning scenario unless a shared helper is introduced deliberately.
